// apps/console/server/plan.ts (sketch)
export async function getPlanForAgent(threadId) {
  const { plan_doc, plan_md } = await getThread(threadId);
  const threads = await threadStore.getThreads();

  // Walk plan_doc, find every commentThread mark, collect its inline text
  // and the sentence it sits in.
  const anchors = extractAnchors(plan_doc);
  // → [{ threadId: "t_abc", anchor_text: "presigned URL",
  //      context: "Use multipart form upload with a presigned URL." }]

  return {
    markdown: plan_md,
    comments: anchors.map((a) => {
      const t = threads.get(a.threadId);
      return {
        id: a.threadId,
        anchor_text: a.anchor_text,
        context: a.context,
        resolved: t.resolved,
        thread: t.comments.map((c) => ({
          author: c.userId,
          text: bodyToText(c.body),  // flatten BlockNote blocks → string
          at: c.createdAt,
        })),
      };
    }),
  };
}
Why a side-channel and not inline markdown markers? Markdown has no comment syntax. Inlining markers (e.g. {{comment:t_abc}}…{{/comment}}) would force the Agent to write them back exactly — high foot-gun. A side-channel keeps the markdown clean and pushes anchor-matching to the server, where we can be deliberate.
↓   Agent decides: "good point — add the lifetime constraint to the line." Calls tempo_write_plan(thread_id, new_markdown).
Stage 4

Agent writes back. Server reconciles the comment anchor.

Agent ships fresh markdown. Server parses to a new block tree, walks every existing thread mark, and re-anchors by substring-matching anchor_text then context. The comment stays attached to the rewritten line; if the anchor text vanished entirely, the thread is flipped to orphaned.

Reconciliation rule. Match priority: (1) exact anchor_text substring in the new block tree → re-anchor; (2) anchor_text within a one-edit Levenshtein window of any inline run → re-anchor with a "soft" flag; (3) context substring anywhere → re-anchor at the closest containing block; (4) no match → set thread.metadata.orphaned = true and leave it visible in the sidebar. This is structurally the same logic as the existing reconcileCommentAnchors in apps/console/server/comments.ts, just operating on BlockNote inline runs instead of Tiptap CommentMark ranges.
Storage shape, when this leaves the playground: two columns on the existing threads row — plan_doc (BlockNote block-tree JSON, replaces today's Tiptap JSON) and plan_md (cached derived markdown). The threadStore is a new pair of tables — plan_threads(thread_id, plan_id, resolved, metadata) and plan_thread_comments(comment_id, thread_id, user_id, body_blocks, created_at) — with a small ThreadStore implementation that reads/writes those tables (this is what BlockNote calls a "custom ThreadStore" — they ship YjsThreadStore, TiptapThreadStore, RESTYjsThreadStore; we'd add TempoThreadStore). Comments and replies do not need a Yjs document at rest — only the playground uses Yjs because it's the path of least resistance for an in-memory single-user demo.
