Tempo — System architecture

Single page reference: where we are after slices 1a + 1b, what slice 1c lands, and what the system looks like when slices 2 (Hosted runtime) and 3 (Gateway + Connectors) ship behind it. Authored against plans/agent-harness.md and the slice plans.

Thesis (one paragraph)

Tempo is the human-in-the-loop planning layer between intent and agent execution. The Plan is the deliverable; everything else is scaffolding. There is one Agent identity (the LLM) reachable through two runtimes — Local (the Member's own claude binary talking to Tempo over remote MCP) and Hosted (an Agent SDK loop in an ephemeral VM, driven by Worker). Both speak the same tempo_* MCP contract against the same Worker. Worker owns all agent-touched data, governs every connector call through the Gateway, and persists artifacts (Plans, Comments, Discussion, events) — never agent process state. Console is UI + Workspace admin only.

After slice 2 — Hosted runtime future

Worker gains an asynchronous brain: a Postgres-outbox-backed Mailbox that coalesces incoming events (Comment / Message / Recheck) into batched turns, plus an Agent SDK loop running inside an ephemeral, egress-locked VM. Runtime routing per event: if an active Local Session exists, route Local; else (and only if Workspace has Hosted enabled), wake Hosted.

After slice 3 — Gateway + Connectors future

Worker's MCP surface becomes governed. Every connector call flows through a fixed middleware pipeline. Per-Connector auth granularity: Workspace-scoped (GitHub App, Notion internal), Member-scoped (Linear), or hybrid. Grants live in self-hosted Nango; the data path stays in Worker.

Two exit paths from the VM: repo I/O goes direct to GitHub with a scoped git token (the local-disk work the VM exists for); governed connector calls loop back through Worker's Gateway. The VM can reach exactly three things: Anthropic API, GitHub, Worker.

Build roadmap

Five slices. 1a + 1b shipped. 1c is the topology flip. 2 + 3 add the Hosted runtime and the Gateway with first Connector.

1a
shipped Extract packages/db
  • Lifted Drizzle schema + client + migrations + newEventId into a workspace package.
  • 13 Console consumers re-pointed to @tempo/db/*.
  • Pure refactor; no behavior change. Five reviewer-found fixes applied.
1b
shipped apps/worker skeleton with stub tempo_attach
  • Express + MCP SDK v1.29 StreamableHTTPServerTransport at /mcp.
  • Per-session McpServer; Mcp-Session-Id binds to workspaceId for cross-workspace isolation.
  • One stub tempo_attach reading via @tempo/db; field-shape parity with Console's existing GET /api/sessions/:id/state.
  • Dockerfile + fly.toml v2 schema; fly deploy stays manual.
1c
next Migrate routes + reshape CLI
  • 17 routes + 14 server modules move from Console to Worker.
  • All 10 tempo_* tools registered on Worker.
  • CLI rewritten: tempo-agent init (OAuth → ~/.tempo/) + tempo-agent connect <thread-id> (spawn claude stream-json wrapper).
  • Browser writes re-pointed to Worker (Bearer Clerk JWT, CORS).
  • New: user_tokens table, /cli/authorize page, /api/cli/* + /api/agent-events on Worker.
  • Hard cutover: @gmeher/tempo-agent@1.0.0 on npm; design partners migrated.
2
future Hosted runtime (Mailbox + SDK loop + VM)
  • Postgres-outbox Mailbox with 60s debounce + per-Thread coalescing.
  • Hosted Agent SDK loop driver — system prompt for planning behavior, canUseTool hook.
  • Ephemeral VM (Fly Sprites) with egress allowlist (Anthropic + GitHub + Worker only).
  • Per-turn lifecycle; rebuild from artifact via tempo_attach (no checkpoint).
  • Workspace-level Hosted toggle; runtime routing per event.
3
future Gateway + first Connector + allowlist + approve-gate
  • Gateway middleware: allowlist → approve-gate → grant resolution → execute → provenance → redact → audit.
  • Self-hosted Nango in VPC; connectionId structure for Workspace / Member / Hybrid grants.
  • First Connector: GitHub or Linear (decided at slice-3 start). First-party MCP via DCR.
  • Console UI: Workspace admin Integrations section + per-Thread Allowlist control.
  • Per-Member rate limiting folds in here.
