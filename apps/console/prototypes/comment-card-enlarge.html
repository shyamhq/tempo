Agent Instruction & Skill Map

Every instruction, tool, hook, and skill the Tempo planning Agent receives — mapped by lifecycle stage. Sourced from apps/agent/src/ and apps/console/server/workflow.ts. Descriptive map of the current state; improvement ideas live in the Discussion.

How instructions reach the Agent

Four channels. No Superpowers skills, no CLAUDE.md, no system-prompt override at runtime. The CLAUDE.md in the repo root governs build-time AI (us), not the planning Agent.

  1. Spawn args — --settings hooks JSON, positional initial prompt string
  2. MCP tool descriptions — tempo_attach delivers the WORKFLOW guide + full thread state; tempo_poll delivers event payloads 14
  3. WORKFLOW guide — carries detailed prose governing when and how to call it (tone, HTML contracts, …) 3
  4. tempo_poll hook — injects a one-line string into Claude's stdin when Dev activity arrives

Stage 1 — connect

Files: cli.ts (CLI entry) / session.ts (POSTs to /api/sessions with repo path + git remote → session ID + thread ID returned → driver picks up env TEMPO_AGENT_DRIVER)

Stage 2 — Claude spawn

Files: pty-terminal.ts (pty driver) / stream-pump.ts (stream-json driver)

  • Initial prompt (only instruction at spawn): "Call tempo_attach to begin."
  • Allowed tools — both drivers (14 total): tempo_attach, tempo_pull_plan, tempo_update_plan, tempo_update_block, …

Stage 3 — attach handshake

Files: server/mcp/tools/tempo-attach.ts

Returns: WORKFLOW guide (hardcoded constant), full thread state snapshot, conversation history, current plan, list of unresolved comments and clarification rounds.

Stage 4 — work loop

The Agent draws on the WORKFLOW guide for tone and block-surgery contracts, on tool descriptions for wire format, and on event payloads for new Dev activity. There is no other instruction channel.
